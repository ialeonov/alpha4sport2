### СЦЕНАРИЙ 2: "Хочу масштабироваться, но безопасно"

```
ВЫБОР: Вариант 2 (гибридный) ✅ РЕКОМЕНДУЕТСЯ
ПРИЧИНА: Максимум контроля + максимум гибкости
РЕАЛИЗАЦИЯ: 10 дней разработки
PAYOFF: Персонализация + масштабируемость
```

### СЦЕНАРИЙ 3: "Хочу AI-первый, напиши мне идеальный коуч"

```
ВЫБОР: Вариант 3 (полностью ИИ)
ПРИЧИНА: Максимальная персонализация
РИСК: Дорого ($30K/мес), может ошибаться

             (когда будут данные для fine-tuning)

## АРХИТЕКТУРНЫЕ РАЗЛИЧИЯ

### ВАРИАНТ 1: Rules-Based (Текущий)

```
User: "Генерируй тренировку"
        ↓
[Python: hardcoded rules]
  • _EXCLUDED_MUSCLES = {...}
  • _TIER2_MUSCLES = {...}
  • _MUSCLE_TO_PATTERNS = {...}
  • scoring formula: (days * 1.4) - (sets * 2.8) - ...
        ↓
[LLM Prompt with rules inline]
  "Мышцы с recovery_status='blocked' нельзя включать"
  "Следуй этим ПРАВИЛАМ генерации..."
        ↓
Claude API
        ↓
Workout JSON ✅

ПРОБЛЕМЫ:
❌ Правила в коде → нужна перекомпиляция
❌ Коэффициенты забиты → нельзя тюнить
❌ Не адаптивны → одна конфигурация для всех
```

### ВАРИАНТ 2: Hybrid (Рекомендуется)

```
User: "Генерируй тренировку"
        ↓
[SELECT MuscleConfig WHERE user_id = ?]  ← Из БД!
  • tier 1, 2, 3, null
  • min_days_between_training
  • target_volume_week_sets
        ↓
[SELECT MovementPattern WHERE user_id = ?]  ← Из БД!
  • pattern name, target muscle, priority
        ↓
[SELECT VolumeGuidance WHERE user_id = ?]  ← Из БД!
  • ideal sets/reps по целям
        ↓
[LLM Prompt with DATA]
  "Используй эту конфигурацию при генерации:
   {
     muscleConfiguration: [...],
     movementPatterns: [...],
     volumeGuidance: [...]
   }"
        ↓
Claude API
        ↓
[Validation: упражнения есть, мышцы не blocked, etc]
        ↓
Workout JSON ✅

ВЫИГРЫШИ:
✅ Правила в БД → легко менять без кода
✅ Коэффициенты динамические → можно тюнить
✅ Можно персонализировать → разные configs per user
✅ Масштабируемо → новая мышца = INSERT row
✅ Обновляется без перезагрузки → on-the-fly
```

### ВАРИАНТ 3: AI-First (Future)

```
User: "Генерируй тренировку"
        ↓
[Context Summary: история, прогресс, preference, feedback]
        ↓
[System Prompt without explicit rules]
  "Ты персональный тренер. Зная историю этого пользователя,
   создай тренировку которая:
   - Соответствует восстановлению (48ч правило)
   - Балансирует мышцы (не перегружай одну)
   - Прогрессирует (улучшай результаты)
   - Уважает травмы
   - Следует целям (масса/сила/похудение)"
        ↓
Claude API
        ↓
[LLM сам решает all rules]
        ↓
[Validation: упражнения есть в каталоге]
        ↓
[Feedback Loop: сохранить что пользователь выполнил]
        ↓
[Next Time: контекст включает "в прошлый раз выполнил X"]
        ↓
Workout JSON ✅ (обучается от feedback)

ВЫИГРЫШИ:
✅ Максимальная персонализация
✅ Обучается на каждый feedback
✅ Может адаптировать правила сам
✅ Может порекомендовать новые упражнения

ПОТЕРИ:
❌ Дорого ($30K/мес для 100K users)
❌ Медленнее (2-5 сек вместо instant)
❌ Может ошибаться (hallucinate)
❌ Сложно дебажить ("почему он так решил?")
```

ДЕЙСТВИЕ: Ничего не менять, сосредоточиться на других фичах

### ФАЗА 1 (1-2 недели) - ВАРИАНТ 2

```
ЭТАП 1.1: Создать таблицы БД (день 1-2)
├─ MuscleConfig (muscle, tier, min_days, target_volume)
├─ MovementPattern (pattern, muscle, priority)
└─ VolumeGuidance (goal, sets, reps, rest, notes)

ЭТАП 1.2: Миграция данных (день 2-3)
├─ Заполнить дефолты из констант
├─ Создать fixtures для тестирования
└─ Провер миграцию

ЭТАП 1.3: Переработать coach_service.py (день 3-4)
├─ _get_muscle_config(db, user_id) → читает из БД
├─ _get_movement_patterns(db, user_id) → читает из БД
├─ _get_volume_guidance(db, user_id) → читает из БД
└─ Всё остальное как было, но с данными из БД

ЭТАП 1.4: Обновить prompts (день 4-5)
├─ System prompt включает конфиг из БД
├─ LLM получает структурированную информацию
└─ Всё остальное как было

ЭТАП 1.5: Тестирование (день 5-6)
├─ Unit tests для новых методов
├─ Integration tests (E2E)
├─ Manual testing с разными конфигами
└─ Performance check (нет ли новых N+1 queries)

ЭТАП 1.6: Документация (день 6-7)
├─ Как добавить новую мышцу
├─ Как тюнить коэффициенты
├─ Как персонализировать для пользователя
└─ Database schema docs

ИТОГО: 1-2 недели (50 часов разработки)
ВЫИГРЫШ: Масштабируемость + гибкость
```

### ФАЗА 2 (2-3 недели) - ОПЦИОНАЛЬНО

```
ЭТАП 2.1: UI для управления конфигурацией
├─ Админ-панель (edit muscle tiers, patterns)
├─ User settings (personalize volume guidance)
└─ Presets (push-ups only, legs only, full-body, etc)

ЭТАП 2.2: Feedback Loop
├─ Сохранять что пользователь выполнил
├─ Сохранять изменения (заменил упражнение X на Y)
├─ Анализировать pattern (какие упражнения популярны)
└─ Использовать в next generation

ЭТАП 2.3: Learning Layer (простой)
├─ Если пользователь часто меняет "ноги" на "спину" → swap priority
├─ Если пользователь добавил 50 новых упражнений → обновить patterns
├─ Если не выполняет одно упражнение → убрать его из candidates
└─ Всё на simple rules-based logic, не LLM
```

### ФАЗА 3 (3-4 недели) - FUTURE

```
ЭТАП 3.1: Fine-tuning LLM
├─ Если у нас есть 1000+ примеров "user requested X, did Y"
├─ Можем fine-tune small LLM (не Claude)
├─ Или создать RAG (retrieval) для подобных случаев
└─ Полная AI-first система

ЭТАП 3.2: Monetization
├─ "AI-Coach Pro" → full personalization
├─ "Coach-Insights" → analyze performance trends
└─ Premium features на основе AI
